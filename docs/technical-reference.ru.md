# Технический справочник AI Browser

[English README](../README.md) · [Русский README](../README.ru.md)

Здесь сохранены подробности инструментов, привязки вкладок, восстановления соединения и протокола из прежнего README. AI Browser подключается к Codex и Claude через MCP; разделы о конфигурации и служебных командах конкретного клиента отмечены отдельно. Для установки и начала работы используйте README. Отметки версий описывают, когда появилась функция; отдельные инструкции по переходу со старых версий относятся к соответствующим обновлениям.

## MCP-сеансы и инструменты

Сервер предоставляет `browser_restart`, `browser_status`, `browser_archive_commands`, `browser_connections`, `browser_bind_connection`, `browser_windows`, `browser_bind_window`, `browser_tabs`, `browser_context`, `browser_snapshot`, `browser_screenshot`, `browser_beforeunload`, `browser_open`, `browser_navigate`, `browser_switch`, `browser_click`, `browser_click_at`, `browser_fill`, `browser_press_key`, `browser_type_text`, `browser_select`, `browser_upload_file`, `browser_batch` и ресурс `browser://context`. Для работы с существующей страницей агент запрашивает контекст выбранной вкладки; при открытии указанного сайта может сразу использовать `browser_open`. Содержимое страниц остаётся недоверенными данными. Сам запуск MCP, initialize и обнаружение инструментов не открывают Chrome и не читают страницы. API-ключи OpenAI/Anthropic для сервера не нужны: браузером управляет выбранный MCP-клиент, например Codex или Claude.

Для каждого stdio-подключения создаётся случайный ID. Новые группы называются **AI Browser**. При выборе окна расширение ищет свободную **AI Browser**; группы старых версий с именем **AI Browser · Codex XXXXXX** тоже поддерживаются. Если активная вкладка входит в такую группу, выбирается она; иначе — первая подходящая по ID. Если свободной группы нет, она создаётся при первом `browser_open` или `browser_navigate`, сразу с запрошенным адресом. Произвольные пользовательские группы не присоединяются. Группы, занятые другими MCP-сессиями (включая их привязки в других окнах), остаются отдельными. При окончательном закрытии внешнего MCP-подключения привязка освобождается, вкладки остаются и могут использоваться следующим подключением. Замена backend через `browser_restart` сохраняет привязку. Доступ к вкладкам после привязки проверяется по ID группы при каждой команде.

Новое MCP-подключение в macOS ищет однозначно определённое окно Chrome на текущем Space активного дисплея. Выбранные профиль и окно закрепляются за сессией. Для смены окна уже работающего MCP-подключения попросите агента вызвать `browser_windows`, затем `browser_bind_window`. Перетаскивание страницы в группу конкретного MCP-подключения делает её доступной для явного выбора; содержимое других вкладок автоматически в контекст не добавляется. Кнопки popup управляют общей группой CLI; они не меняют группы уже работающих MCP-процессов.

Сервер использует официальный SDK MCP 2.3.0 и stdio, не открывает HTTP-порт. Chrome продолжает работать в фоне; активность пользователя на целевой вкладке не приостанавливает команды агента. Ошибки возвращаются как MCP `isError` со структурированной причиной, без повторного выполнения действий. Для изоляции требуется расширение **0.4.0**; старые версии отклоняются с просьбой обновления.

[Документация подключения Codex](https://learn.chatgpt.com/docs/extend/mcp?surface=cli), [подключение Claude Code](https://code.claude.com/docs/en/mcp), [официальный Python SDK MCP](https://github.com/modelcontextprotocol/python-sdk).

## Универсальный клик по изображению (0.13.0)

Для обычных элементов используйте селекторы из `browser_snapshot` и команды
`browser_click`, `browser_fill`, `browser_select`. Если виджет не предоставляет
подходящего элемента в DOM, агент может посмотреть `browser_screenshot(tab_id=...)`
и вызвать `browser_click_at(screenshot_id=..., x=..., y=..., tab_id=...)`.
Скриншот возвращается изображением JPEG вместе с `screenshot_id` и размером
`viewport`; координаты клика задаются в CSS-пикселях от левого верхнего угла
видимой области страницы (`coordinate_system: "css_viewport"`). Размер JPEG
указан в `image_width`, `image_height` и может быть уменьшен. Перевод точки
из изображения: `x = image_x × viewport.width / image_width`,
`y = image_y × viewport.height / image_height`. Изображение охватывает страницу;
панели Chrome и системные окна в него не входят.

Для нативного календаря Chrome и других всплывающих элементов используйте
`browser_screenshot(tab_id=..., native=True)`, затем тот же `browser_click_at`.
Тип ввода определяется по `screenshot_id`: снимок с `capture_method: "native"`
использует системную мышь macOS. Клик не зависит от CSS-селектора, типа виджета
или формата значения. Нативный снимок охватывает видимую область выбранной
страницы вместе с её всплывающими элементами. Обычный CDP-клик может закрыть
встроенный календарь Chrome без выбора дня, поэтому для него выбирайте
нативный режим заранее, без повторения неопределённого клика.

Для этого режима нужны разрешения macOS **Универсальный доступ** и
**Запись экрана** для приложения, запускающего MCP (например, Codex или
Terminal). Целевая вкладка и окно Chrome должны быть активны и видимы;
инструмент сам не активирует окна и не переключает вкладки. Перед нажатием
проверяются процесс Chrome, окно, документ, рабочий стол, геометрия и
перекрытие другими приложениями. При смене фокуса ввод останавливается.
Системный режим доступен через MCP на macOS; обычные клики по странице
продолжают работать в фоне.

Клик использует последний скриншот той же сессии и вкладки, действительный
30 секунд. Перезагрузка документа, изменение прокрутки или размера видимой
области требуют нового скриншота. После попытки клика снимок считается
использованным; другие действия с вкладкой также требуют нового снимка.
Эти проверки не гарантируют, что содержимое страницы не
перестроилось внутри прежней области: выбирайте точку по свежему изображению
и проверяйте результат. При `recovery_action: "refresh_screenshot"` агент сам
получает новый скриншот и заново выбирает цель.

Для управления виджетами с клавиатуры есть
`browser_press_key(selector=..., key="ArrowDown", tab_id=...)` с необязательными
`modifiers` (`Alt`, `Control`, `Meta`, `Shift`). Поддерживаются стрелки, `Enter`,
`Escape`, `Tab`, `Backspace`, `Delete`, `Home`, `End`, `PageUp`, `PageDown`, `Space`
и отдельные печатные ASCII-символы. Команда
`browser_type_text(selector=..., text=..., tab_id=...)` вставляет текст средствами
Chrome в редактируемое поле. Для замены всего значения используйте `browser_fill`.
Ввод отправляется через Chrome DevTools в закреплённую вкладку, сохраняя фокус
пользовательского окна. Для same-origin iframe укажите `frame_selector` из снимка.
Поля пароля и загрузки файла защищены; для файлов есть `browser_upload_file`.

При необходимости поле также можно заполнить напрямую:

```text
browser_fill(selector="#date", text="2026-11-13", tab_id=123)
browser_fill(selector="#time", text="12:00", tab_id=123)
browser_fill(selector="#datetime", text="2026-11-13T12:00", tab_id=123)
```

Для прямого заполнения `browser_snapshot` показывает формат значения (`value_format`) и ограничения
`min`, `max`, `step`. Формат даты в поле — `YYYY-MM-DD`, даже если на экране она
выглядит как `Nov 13, 2026`. Перед заполнением структурированного поля расширение
проверяет значение средствами браузера: неверная дата не должна очищать прежнюю.
После ввода агент получает новый снимок и сверяет значение и валидацию;
успешная отправка ввода сама по себе не подтверждает сохранение на сервере сайта.
Для обычного HTML `select` продолжайте использовать `browser_select`.

После изменений Python-кода агент сам вызывает `browser_restart` и проверяет
сохранение вкладки. Если клиент Codex сохранил старый список инструментов,
`scripts/codex_mcp.py refresh` ставит его обновление в очередь через
[штатное API Codex](https://learn.chatgpt.com/docs/app-server).
Команда `call` этого помощника позволяет обращаться к новым инструментам уже
в текущем ходе через то же MCP-подключение текущего диалога, без смены группы.
Ручное переподключение пользователем для этого не требуется.
Изменения самого Chrome-расширения применяются отдельно: перезагрузите
AI Browser в `chrome://extensions`.

## Выбор при предупреждении о несохранённых изменениях (0.14.0)

Агент сам выбирает ответ на Chrome `beforeunload`: `browser_beforeunload`
сначала читает предупреждение, затем применяет `leave` или `stay` к полученному
`dialog_id` с обязательной причиной решения. Решение основано на истории
действий агента и задаче. Сохранённые или ненужные воспроизводимые изменения
можно оставить; нужные несохранённые, чужие или неизвестные изменения сначала
сохраняются выбором «Отмена». Отдельное подтверждение каждого такого окна
пользователем не требуется. Сам мост не оценивает важность текста формы.
Выбор и его краткое обоснование сохраняются в локальном checkpoint MCP для
проверки результата и разбора сбоев; значения полей в обоснование включать не нужно.

Расширение заранее наблюдает за диалогами закреплённых вкладок, поэтому
блокирующее окно возвращается агенту как `blocked` вместо запуска очередного
ввода вслепую. Для наблюдения соединение Chrome debugger сохраняется, пока
контекст принадлежит агенту; в Chrome может оставаться полоса отладки.
При закрытии контекста или отзыве доступа соединение освобождается.
После ответа агент проверяет результат: `leave` может завершить исходную
навигацию или закрытие вкладки, а частично выполненный ввод не повторяется.

Уже открытое до подключения предупреждение в macOS обрабатывается через
Accessibility. Поддерживаются точные стандартные английские и русские варианты
Chrome; подтверждения сайтов, разрешения, файловые окна и неизвестные локали
не принимаются этим способом. Ответ связан с конкретным диалогом и вкладкой,
однократен и действует 30 секунд. Нативный путь требует активного закреплённого
окна Chrome и разрешения «Универсальный доступ».

## Перезапуск backend без потери вкладки (0.12.0)

`browser_restart()` загружает Python-код с диска в новый процесс backend.
Внешний stdio-канал MCP остаётся открытым: постоянный supervisor передаёт запросы
новому процессу после его подготовки. ID MCP-сессии, закреплённое подключение
Chrome, окно, группа, вкладка, сайт и `context_id` сохраняются. Успешный ответ
позволяет проверить новый PID backend и загруженную версию; история диалога
выбранного MCP-клиента продолжает существовать.

Команда перезапускает backend AI Browser, сохраняя работающий Chrome и его
вкладки. Ранее отправленные клики, ввод и другие действия не повторяются.
Если есть незавершённые запросы, ответ содержит `code: "restart_busy"`,
`retryable: true` и `requires_user_action: false`. Агент дожидается их завершения
и повторяет только `browser_restart()`. Если новый backend не удалось подготовить,
прежний процесс продолжает обслуживать соединение.

При первом обновлении с версии без `browser_restart` один раз переподключите MCP
средствами выбранного MCP-клиента, чтобы появился новый инструмент. Затем обновления
Python-backend применяются через `browser_restart()`. Правки файлов расширения
Chrome по-прежнему требуют его перезагрузки в `chrome://extensions`.
Замена backend сама по себе не гарантирует повторный `initialize` внешнего клиента
или обновление закэшированных им описаний инструментов.

## Подключение и группа

Расширение соединяется с native host в фоне. Иконка анимируется при подключении и работе, зелёная точка означает готовность, красная — ошибку; подробность видна в подсказке и popup. Фоновое подключение не читает страницы и не создаёт группу.

`context`, `tabs`, выбор окна через `browser_bind_window` или popup используют существующую свободную группу, если она найдена. Если группы ещё нет, команды чтения возвращают пустые списки страниц и вкладок. Первое открытие адреса через `open` / `new` или `navigate` создаёт голубую группу **AI Browser** и её первую вкладку сразу с запрошенным сайтом. Новые страницы через `new` и ссылки `target=_blank` из группы добавляются в неё. В popup можно добавить текущую вкладку. Также вкладки можно переносить в группу вручную средствами Chrome.

Каждая команда проверяет фактический `groupId`. Вкладки вне группы недоступны. После переноса вкладки наружу её текущее содержимое перестаёт считываться; содержимое, уже попавшее в историю диалога, остаётся историей до `/clear` или новой сессии. Название группы не предоставляет доступ само по себе: хранится конкретный ID группы в `storage.session`.

`context` по умолчанию читает только выбранную вкладку; текст страницы ограничен, ответ явно сообщает об этом. `tabs` перечисляет метаданные вкладок для явного выбора, `snapshot --tab-id` даёт подробности нужной страницы и уникальные CSS-селекторы. Недоступные или ещё не готовые страницы возвращаются с индивидуальной ошибкой. При запуске нового задания ai-cli добавляет контекст выбранной страницы к пользовательскому сообщению как недоверенные данные.

## Контекст отдельной вкладки (0.10.0)

`browser_context(tab_id=123)` читает только указанную вкладку текущей группы.
Без `tab_id` выбирается текущая логическая вкладка агента. По умолчанию
`all_tabs=False`: ответы с содержимым страницы и сопутствующими метаданными
ограничены этой вкладкой. Для чтения нескольких вкладок требуется явная просьба
пользователя. Если указаны конкретные вкладки, агент читает только их по `tab_id`.
`browser_context(all_tabs=True)` используется только при явном запросе всей группы.
`browser_tabs` остаётся списком метаданных для выбора вкладки и не читает её DOM.

У каждой вкладки есть отдельный `context_id`, сохраняемый в `storage.session`.
Новая вкладка получает новый ID, в том числе когда первая вкладка создаётся через
`navigate`. `browser_open` возвращает этот ID вместе с ID вкладки. ID контекста
существующей вкладки сохраняется при перезапуске фонового worker в пределах той
же браузерной сессии.

Для применения версии 0.10.0 перезагрузите расширение и MCP-подключение, чтобы
клиент получил новую схему `browser_context` с параметрами `tab_id` и `all_tabs`.

Backend ограничивает получаемые данные страницы. Историю уже состоявшегося диалога
AI-клиента он не удаляет. В Codex, чтобы новая отдельная вкладка обрабатывалась без истории
предыдущей задачи, skill направляет её открытие и обработку отдельному агенту,
когда среда предоставляет создание агента без наследования переписки. Для
`collaboration.spawn_agent` используется `fork_turns="none"`; передаются текущая
задача, URL и известные идентификаторы целевого подключения, окна и контекста.
Старые снимки и тексты других страниц в эту задачу не копируются. Первый вызов
для работы со страницей — `browser_open(URL)`, без подготовительного
`browser_context`, который мог бы прочитать старую страницу из свободной группы.
Предварительная пассивная проверка `browser_status` допускается. Делегирование
через инструкции skill поддерживается в [локальных клиентах Codex](https://learn.chatgpt.com/docs/agent-configuration/subagents).

Открывать URL предпочтительно сразу в MCP-сессии нового агента: отдельная
MCP-сессия может не иметь доступа к группе родителя. Передача `tab_id` или
`context_id` сама по себе не даёт такого доступа и не заменяет проверку принадлежности
вкладки группе. Когда инструмент создания
агента без истории недоступен, действует ограничение чтения одной вкладки;
полный сброс истории Codex не заявляется.

## Несколько окон и рабочих столов macOS (0.9.0)

При первом обращении MCP определяет текущий Space и активный дисплей macOS, затем сопоставляет обычные окна Chrome по процессу браузера и геометрии окна. Выбор выполняется по одному снимку состояния ОС в момент обращения. Если сопоставление не даёт однозначного результата, используется единственное активное обычное окно Chrome по данным расширений. Найденные профиль и окно закрепляются за сессией; дальнейшая смена Space или фокуса не меняет привязку.

В выбранном окне расширение ищет свободную группу AI Browser. Если подходящей группы нет, она создаётся при первом открытии запрошенного адреса, рядом с активной вкладкой и без переключения фокуса. Исходная вкладка не перемещается в группу и не считывается автоматически.

Чтобы выбрать окно явно, откройте значок расширения именно в нужном окне и нажмите **«Работать в этом окне»**. Popup передаёт ID своего окна, поэтому фоновый процесс не угадывает его через `currentWindow`. Для каждого выбранного окна запоминается его группа на время работы расширения, когда она появляется. Выбор окна сам по себе не создаёт вкладок; повторный выбор возвращает прежнюю группу, если она сохранилась. Обычные переключения окон не меняют привязку агента и не переносят вкладки между окнами. **«Добавить эту вкладку»** включает текущую страницу в группу этого же окна.

Если сопоставление по Space неоднозначно или не нашло окна, сервер выбирает единственное активное обычное окно Chrome. Если и активное окно определить однозначно нельзя, сервер возвращает `window_selection_required`. Укажите окно через `browser_bind_window(window_id)`; если его ID принадлежит одному подключению, сервер сам определит владельца. Для явного выбора профиля доступен `browser_bind_connection(connection_id)`. Уже выбранное подключение не подменяется другим профилем по текущему Space.

Определение Space использует метаданные окон macOS и внутренний API SkyLight. Оно не переключает рабочие столы и не активирует окна. Если API недоступен, сначала используется единственное активное обычное окно Chrome, затем — единственное обычное окно единственного подключения либо окно, явно выбранное через popup в единственном профиле. В остальных случаях требуется явный выбор окна. Свёрнутые окна и инкогнито не выбираются автоматически. CLI сохраняет прежний выбор окна через popup или последнее активное окно Chrome.

Определение активной вкладки внутри выбранного окна использует `active: true` и конкретный `windowId`, как в [официальном API Chrome](https://developer.chrome.com/docs/extensions/reference/api/tabs).

## Одновременная работа с пользователем

Новые вкладки создаются в фоне (`active: false`). `switch` меняет только выбранную вкладку агента и не меняет активную вкладку Chrome. Автоматический запуск Chrome использует фоновый режим `open -g`. Команды DOM направляются по конкретному `tab_id`, без глобальных клавиш, мыши и буфера обмена. Работа пользователя в других вкладках и приложениях не перенаправляет действия агента.

Действия выполняются и на активной вкладке пользователя: просмотр, ввод и переключение фокуса не вызывают паузу `user_active`. Команды продолжают обращаться к выбранному `tab_id` и конкретному элементу. Одновременное редактирование одного поля пользователем и агентом может изменить один и тот же текст; после действий проверяйте снимок. Границы группы, проверки origin и состояния элементов сохраняются.

### Отправка клика и проверка результата (0.11.1)

Перед нажатием расширение ожидает стабилизации прокрутки и положения элемента:
до 1,5 секунды и не более 30 проверок. После наведения нужны две одинаковые
проверенные точки с интервалом 40 мс. При движении точка пересчитывается;
обычный сдвиг страницы сам по себе не отменяет клик. При этом исходные документ,
элемент и принадлежность группе проверяются повторно. После начала нажатия
стабилизация больше не запускается: повторяется только подготовка, не сам клик.

`browser_click` направляет мышиный ввод через Chrome DevTools Protocol в закреплённую
вкладку по `tab_id`. Для страницы включается эмуляция фокуса; само расширение
не активирует окно и не переключает Space. Сайт, получив ввод, может самостоятельно
открыть окно или изменить фокус, поэтому поведение страницы проверяется после клика.

Успешный ответ содержит `clicked: true`, `input_method: "cdp"`,
`input_dispatched: true`, `effect_confirmed: false` и `verification_required: true`.
Это подтверждает отправку ввода. Сохранение формы, открытие меню или другое
действие сайта подтверждается свежим `browser_snapshot` той же вкладки и контекста.
Для HTML `<select>` сохраняется ответ `clicked: false` / `requires_selection: true`;
выбор пункта выполняется через `browser_select`.

Ошибки клика возвращают структурированную причину:

| Код | Причина |
| --- | --- |
| `click_debugger_unavailable` | Не удалось подключить debugger или подготовить CDP-ввод. |
| `click_target_unavailable` | Элемент недоступен для клика, например скрыт, отключён или перекрыт. |
| `click_target_changed` | Страница или выбранный элемент изменились до отправки ввода. |
| `click_dispatch_failed` | Отправка ввода завершилась ошибкой. |

Все эти ошибки имеют `retryable: false`. До отправки ввода ответ содержит
`action_may_have_run: false` и `input_dispatched: false`. После начала отправки
событий `action_may_have_run: true` означает, что действие могло выполниться;
доставка полного клика может оставаться неизвестной. Отсутствующее поле
`input_dispatched` не означает, что ввода не было. Сам вызов не повторяется
автоматически, включая ошибки после движения мыши или нажатия кнопки.

Начиная с 0.11.1, ошибки `click_target_changed` и `click_target_unavailable`,
для которых `action_may_have_run: false`, возвращают `requires_user_action: false`
и `recovery_action: "refresh_snapshot"`. Агент сам вызывает `browser_snapshot`
для той же вкладки, заново находит актуальную цель и продолжает задание по новому
состоянию страницы. Пользователю не требуется вручную обновлять снимок или кликать.
Старый клик с прежними координатами не пересылается автоматически.
Если ввод мог начаться или его состояние неизвестно, сохраняется остановка
с проверкой результата перед дальнейшими действиями.

## Команды

```sh
ai-browser status                         # только проверка соединения, без вкладок
ai-browser navigate https://example.com   # текущая вкладка группы
ai-browser new https://www.python.org     # новая вкладка той же группы
ai-browser tabs
ai-browser context
ai-browser snapshot --tab-id 123
ai-browser switch 123
ai-browser fill '#search' 'Python' --tab-id 123
ai-browser click 'button[type="submit"]' --tab-id 123
```

Python-интерфейс:

```python
from ai_browser.bridge import request
request({'command': 'open', 'url': 'https://example.com'})
context = request({'command': 'context'})
request({'command': 'snapshot', 'tab_id': context['tabs'][0]['id']})
```

Нейтральная к провайдеру схема инструмента: `ai_browser.schema.SCHEMA`. Внутри одного подключения Chrome команды выполняются последовательно; разные подключения обслуживаются независимо. Действия не повторяются автоматически после потери ответа. Сокеты доступны только текущему пользователю; передача больших сообщений учитывает частичные записи. Страницы считаются недоверенными данными. Пароли, скрытые поля и загрузка файлов через `fill` не поддерживаются; произвольный JavaScript и вкладки вне группы агенту не предоставляются. Iframe того же origin доступны через `frame_selector` из снимка страницы. Кадры другого origin недоступны; Shadow DOM поддерживается.

## Раскрывающиеся списки

Для обычного HTML `<select>` используйте `browser_select`: ровно один из `label` (точное название), `value` или `index` (номер с нуля). Снимок показывает варианты и текущий выбор. Визуально раскрывать системный popup не нужно: выбор выполняется в фоне с событиями `input` и `change`. При нескольких одинаковых названиях или значениях используйте `index`. Для множественного списка выбор добавляется к существующим; остальные пункты не снимаются. Отключённые пункты и поля в отключённом fieldset не изменяются.

```sh
ai-browser select '#genre' --label 'Комедия'
ai-browser select '#genre' --value comedy
ai-browser select '#genre' --index 2
```

Пользовательские меню открываются `browser_click`, затем новый `browser_snapshot` показывает пункты с ролями `option`/`menuitem` и селекторами для следующего клика. CDP-ввод направляется в выбранную вкладку; ответ об отправке не подтверждает, что меню открылось. Активность пользователя не приостанавливает команды. Если после обновления MCP нет инструмента `browser_select`, переподключите сервер или перезапустите AI-клиент.

Для примеров W3Schools Tryit выберите кадр результата явно:

```sh
ai-browser snapshot --frame-selector '#iframeResult'
ai-browser select '#cars' --label Saab --frame-selector '#iframeResult'
```

В MCP те же действия выполняются через `browser_snapshot(frame_selector="#iframeResult")` и `browser_select(selector="#cars", label="Saab", frame_selector="#iframeResult")`. Снимок основной страницы содержит `frames` с доступностью и селекторами iframe. У iframe используется его собственный DOM и конструкторы событий — важно для `about:blank`/`srcdoc` примеров.


### Формы, Shadow DOM и локальные файлы (0.5.0)

`browser_snapshot` обнаруживает `contenteditable`, `role="textbox"`, пользовательские
`radio`/`checkbox`/`switch` и элементы во вложенных открытых и закрытых Shadow DOM
(для закрытых используется Chrome `dom.openOrClosedShadowRoot`). Снимок возвращает
`label`, ограниченное текущее `value`, `checked` (boolean или `"mixed"`), `disabled`,
`required`, `readonly`, `invalid` и `validation_message`. Значения паролей исключены.
В `elements` помещается до 500 элементов с общим бюджетом размера ответа;
поля формы идут перед навигационными ссылками. `elements_truncated` сообщает об обрезке.

Селектор вида `#editor >>> #textbox` означает переход в Shadow DOM. Его нужно
передавать в инструменты без изменений: `browser_fill`, `browser_click`,
`browser_select` и `browser_upload_file` понимают одинаковые пути. `frame_selector`
тоже поддерживает такие пути. Iframe другого origin по-прежнему недоступны.
`browser_fill` поддерживает обычные поля и редактируемые блоки, включая
`contenteditable="plaintext-only"`; роль `textbox` сама по себе не делает блок
редактируемым. Ввод посылает события `input`/`change`, для contenteditable также
отменяемое `beforeinput`. Редакторы, требующие доверенных аппаратных событий или
собственного API, могут отклонить синтетический ввод; результат нужно проверить снимком.

Для файла найдите в снимке `input type="file"` (снимок включает и скрытые поля):

```python
browser_upload_file(
    selector="#upload-dialog >>> input[type=file]",
    paths=["/Users/me/Movies/video.mp4"],
    tab_id=123,
)
```

Используйте фактический селектор из снимка и явно запрошенные пользователем файлы.
Инструмент принимает 1–20 существующих файлов по абсолютным путям на машине Chrome;
несколько файлов допускаются только для поля с `multiple`. Выбор каталогов не
поддерживается. Файл назначается через Chrome DevTools Protocol без системного
диалога и без передачи байтов в контекст агента. Сайт может начать отправку сразу
после выбора; успешный ответ означает выбор файлов, а завершение загрузки
проверяется отдельно по странице. Ограничения размера и формата задаёт сайт.

Для активации обновления перезагрузите расширение на `chrome://extensions` и
разрешите новое разрешение `debugger`, затем перезапустите MCP-подключение своего AI-клиента,
чтобы появился `browser_upload_file`. При выборе файла Chrome может показать
индикатор отладки. Подключение debugger снимается после действия, включая ошибки;
если вкладка уже отлаживается другим клиентом, инструмент возвращает ошибку.
Загрузка также продолжается при активности пользователя; границы группы сохраняются.

После `browser_fill` прочитайте новый `browser_snapshot` и сравните `value` поля
по тому же селектору. Это проверяет состояние формы; сохранение на сервере сайта
нужно подтверждать отдельно по его индикаторам.


### Меньше служебных вызовов (0.6.0)

`browser_batch` выполняет заранее известные действия в одной вкладке одним MCP-вызовом:

```python
browser_batch(tab_id=123, steps=[
    {"command": "fill", "selector": "#title", "text": "Название"},
    {"command": "fill", "selector": "#description", "text": "Описание"},
    {"command": "click", "selector": "#audience-no"},
])
```

Селекторы берутся из предыдущего снимка. Поддерживаются `click`, `fill`, `select`,
до 20 шагов и 60000 символов на пакет. Итоговый снимок возвращается автоматически,
чтобы сравнить значения полей. `frame_selector` задаёт общий iframe и кадр итогового
снимка; в шаге его можно переопределить. Действия, которым нужны новые селекторы,
переход на другую страницу или подтверждение, выполняйте отдельными вызовами.
При первой ошибке пакет останавливается и сообщает `failed_step` (индекс с нуля)
и уже выполненные шаги `completed`. Выполненные действия не откатываются;
повторять весь пакет автоматически нельзя. Смена origin также останавливает пакет.

Строки `Called ai-browser.*` и `Show details` формирует клиент Codex. Каждый вызов
передаётся клиенту как отдельный элемент `mcpToolCall` в [протоколе Codex App Server](https://learn.chatgpt.com/docs/app-server).
Подтверждённой настройки объединения таких карточек в официальном
[справочнике конфигурации Codex](https://learn.chatgpt.com/docs/config-file/config-reference) не найдено.
`browser_batch` объединяет заранее известные действия и итоговый снимок в один
публичный вызов. Когда следующий шаг требует прочитать новый DOM и выбрать селектор,
агенту нужен следующий вызов. Серверный workflow мог бы объединить заранее
определённые операции, но отдельного такого инструмента сейчас нет.
После обновления перезагрузите расширение и MCP-подключение для обнаружения нового
инструмента `browser_batch`.


### Несколько одновременных сеансов Chrome (0.7.0)

Для каждого native-подключения Chrome создаётся отдельный Unix-сокет
`bridge-<connection_id>.sock` в приватной папке текущего пользователя. Глобальный
`host.lock` больше не блокирует второе подключение. Несколько MCP-сеансов могут
работать с разными группами/вкладками одного профиля или с разными профилями Chrome.
Ответы и очереди команд разделены по подключениям; закрытие одного не закрывает
остальные. Отмена клиентского запроса также не завершает native host.

MCP-инструменты `browser_connections` и `browser_bind_connection(connection_id)`
позволяют перечислить и выбрать подключение без запуска Chrome и чтения страниц.
В MCP на macOS первый выбор профиля и окна выполняется по текущему Space активного
дисплея, как описано выше. Для CLI и других платформ сохраняется выбор единственного
подключения либо единственного подключения с активным окном. При неоднозначности
нужен явный выбор. `browser_windows` / `browser_bind_window` выбирают окно внутри
закреплённого подключения.

Выбор профиля закрепляется за MCP-сеансом: смена фокуса и закрытие выбранного Chrome
не перенаправляют команды в другой профиль. Перезапуск native host или фонового
worker восстанавливается автоматически, если сохранилась прежняя браузерная сессия.
Для перехода в другой профиль используйте
`browser_bind_connection` явно. При завершении MCP привязки групп освобождаются
во всех использованных подключениях, страницы остаются открытыми.

Для CLI доступны:

```sh
ai-browser connections
ai-browser status --connection-id CONNECTION_ID
ai-browser context --connection-id CONNECTION_ID
ai-browser snapshot --connection-id CONNECTION_ID --tab-id 123
```

В Python передайте `connection_id` в `request({...})`. Старый `bridge.sock`
распознаётся как подключение `legacy` для совместимости при обновлении.
Старые процессы native host продолжают использовать прежний код до переподключения:
для применения обновления перезагрузите расширение во всех используемых профилях
Chrome и переподключите MCP. Переустановка native manifest не требуется, если его
launcher использует этот установленный проект.

### Автоматическое восстановление после простоя (0.8.0)

MCP запоминает ID браузерной сессии; расширение хранит его и привязки каждого
`session_id` в `chrome.storage.session`. Когда native host или фоновый worker
перезапускается, адрес сокета может измениться. При следующем обращении MCP
проверяет прежний сокет до двух секунд и при обрыве автоматически ищет
прежнюю сессию, ожидая переподключения до 35 секунд.
Окно, группа, выбранная вкладка и ID MCP-сессии сохраняются; процесс MCP
не перезапускается. Восстановление выполняется и при `browser_status`.

У выполняемого MCP-запроса общий лимит ожидания 40 секунд: проверка подключения,
поиск нового сокета и повторное чтение расходуют один бюджет. Отмена прерывает
ожидание переподключения; чтение и запись сокета проверяют отмену не реже чем
каждые 100 мс. Сессия освобождается после остановки обработчика, чтобы отменённая
команда не продолжилась параллельно со следующим запросом.

Временные ошибки транспорта возвращают `requires_user_action: false`.
Для безопасного повтора указаны `retryable: true`, `recovery_action: retry_request`
и задержка `retry_after_ms: 1000`. Если действие могло выполниться до обрыва,
ответ содержит `action_may_have_run: true`, `retryable: false` и предлагает
проверить страницу новым снимком. Ошибки разрешений и необходимость явного выбора
окна по-прежнему требуют действия пользователя.

Подключение из popup ожидает handshake вне очереди браузерных команд. Запоздалые
события закрытого порта не могут отметить новое подключение готовым. Native host
ограничивает 30 секундами чтение всего сообщения, включая неполный заголовок и тело.

Временная ошибка инициализации хранилища не блокирует worker навсегда: следующая
попытка подключения повторяет инициализацию. Параллельные запросы используют одну
попытку. Копии привязки в `storage.session` и `storage.local` имеют номер ревизии.
Восстановление выбирает свежую подтверждённую копию того же профиля и процесса
Chrome; неудачная запись резервной копии не откатывает более свежую сессию.

MCP регистрирует владельца сессии по PID и времени запуска процесса. Для
управляемого backend владельцем является supervisor, поэтому `browser_restart`
не освобождает его группы. Native host проверяет владельцев известных расширению
сессий перед командами. Только подтверждённое завершение процесса или повторное
использование PID позволяет освободить группу; её вкладки остаются открытыми.
Сон, простой, отказ ОС в проверке и отсутствие записи владельца не являются
основаниями для освобождения. Старые сессии без такой записи автоматически
не освобождаются. Для применения протокола очистки обновите расширение: это также
перезапустит native host с новым кодом.

При поддержке `command_journal` действия получают уникальный `request_id`.
Расширение сохраняет начало выполнения до действия и итог до отправки ответа.
После потерянного ответа `browser_status` возвращает `last_command` со статусом
`completed`, `failed`, `started`, `unknown` или `archived`; ID переживает перезапуск backend.
`completed` означает завершение обработчика, а результат на сайте проверяется
снимком. `started` и `unknown` не подтверждают ни успех, ни отсутствие действия:
повторять такую команду автоматически нельзя. Уже записанный ID повторно не
выполняется. Журнал хранит последние 256 завершённых записей и отдельно до 128
незавершённых, без аргументов, введённого текста и содержимого страниц.
Защита от повтора хранится независимо: с `command_sequence` это максимальный
принятый номер для каждой сессии, для старых клиентов — сохранённые ID.
При исчерпании лимита 4096 таких защитных записей новые действия отклоняются
до выполнения; защитные записи автоматически не вытесняются.

`browser_status(request_id="…")` проверяет конкретную команду и возвращает
`command_record`. Поле `unresolved_commands` содержит команды с неизвестным
исходом; новая команда не удаляет предыдущие из этого списка. Список и счётчик
номеров сохраняются в checkpoint backend. Подтверждённые результаты из локального
кэша не заменяются на `unknown`, если запись расширения уже вытеснена. Ошибка
дополнительного чтения журнала возвращается в `journal_error` отдельно от исправного
подключения. Журнал не обещает определить результат после сбоя в любой момент.

`browser_status(reconcile=true)` сверяет все неизвестные исходы одним запросом
к расширению. При достижении лимита 128 backend также пытается выполнить сверку
перед отказом в новой команде. Подтверждённый отказ с `action_may_have_run: false`
сразу записывается как `failed` и не занимает лимит неизвестных исходов.

После проверки страницы можно вызвать
`browser_archive_commands(request_ids=["…"], page_checked=true)`. Архивирование
сохраняет `outcome: unknown` и `action_may_have_run: true`, освобождает место для
новых команд и сохраняет защиту от повтора ID. Оно не объявляет действие успешным
или невыполненным. Без подтверждения проверки страницы, для чужих ID или другого
профиля архивирование отклоняется. Запись архива пакетная: при ошибке хранения
локальные команды не удаляются из списка неизвестных исходов.

Служебная проверка `session_probe` не читает содержимое страниц и не создаёт группы.
Она восстанавливает прежнюю привязку по ID браузерной сессии либо по сохранённому
URL в том же профиле. Если вкладку заменили, используется прежняя группа либо
свободная группа с сохранённым названием. При неоднозначности выбирается группа
в текущем активном окне Chrome; если таких групп несколько — группа активной вкладки.
Группы других MCP-сессий и вкладки вне групп не используются. Для подключения,
ещё не создавшего группу, достаточно ранее подтверждённого ID браузерной сессии.
Потеря ответа на саму проверку не мешает повторному восстановлению, в том числе
после перезапуска worker. Список вкладок, контекст, снимок и статус при обрыве
повторяются один раз после восстановления транспорта. Уже отправленные клики,
ввод и другие действия с потерянным ответом не повторяются.

При полном перезапуске Chrome, перезагрузке или отключении расширения Chrome
[очищает `storage.session`](https://developer.chrome.com/docs/extensions/reference/api/storage#property-session).
Для перезагрузки расширения привязки дополнительно сохраняются в `storage.local`.
Native host передаёт PID и время запуска родительского процесса Chrome; расширение
восстанавливает ID браузерной сессии, привязки и `context_id` только при совпадении
этой метки и профиля. Поэтому перезагрузка расширения в работающем Chrome больше
не требует повторного выбора подключения и окна. Для применения обновления один
раз перезагрузите расширение; резервная копия создаётся при последующих командах.

При смене ID браузерной сессии сервер проверяет сохранённую историю этой MCP-сессии
и тот же профиль, затем ищет прежнюю вкладку или группу по правилам выше.
Новые ID окна и вкладки принимаются автоматически. Завершённая
через `session_release` сессия автоматически не возобновляется. Если совпадений нет
или их несколько, агент проверяет `browser_connections` и сам выбирает прежние
подключение и окно, когда они однозначно известны из текущих метаданных. Наличие
трёх окон само по себе не требует подтверждения. Вопрос пользователю нужен только
при реальной неоднозначности. Уже отправленные действия не повторяются.

Если старый диалог возвращает `launch_timeout`, хотя новые диалоги работают,
проверьте его `browser_status` или `browser_connections`: запущенный Python-процесс
может использовать прежнюю версию кода. Если доступен `browser_restart`, примените
обновление им. Для процесса, ещё не знающего этот инструмент, требуется однократное
переподключение средствами клиента. Особенно это важно при обновлении с общего
`bridge.sock` на отдельные подключения версии 0.7.0.
Обновлённый мост сохраняет ошибки выбора подключения и ожидания ответа вместо
подмены их общим `launch_timeout`.

Для установки версии 0.8.0 один раз перезагрузите расширение и MCP-подключение.
Последующие обрывы native host восстанавливаются без перезапуска MCP.

Для диагностики конкретного диалога используйте `browser_connections` или
`browser_status` именно в нём. Поле `mcp` сообщает PID, загруженную версию,
время создания сессии, пути Python-модулей и выбранное подключение. Оно также
включается в ошибки соединения. Отсутствие этого поля означает, что процесс
ещё не загрузил код с диагностикой. Свежий запуск `ai-browser-mcp --version`
или версия установленного пакета не показывают код, уже загруженный старым
MCP-процессом.

### Сохранённый сайт и привязка (0.9.0)

Ответы расширения содержат `binding`: ID профиля, браузерной сессии, окна, группы
и вкладки, последний проверенный адрес, заголовок, запрошенный адрес и время
обновления. MCP сохраняет подтверждённую привязку своей сессии в диагностике
`mcp.binding`; при ошибке она помечена `binding_status: "last_verified"`.
Общая привязка CLI из служебного `__status` не становится привязкой MCP-сессии.

Расширение хранит до 128 последних записей в `chrome.storage.local`, отдельно от
действующих разрешений в `storage.session`. `profile_id` сохраняется между запусками,
а `browser_instance_id` меняется при новой браузерной сессии. В истории URL сохраняются
без логина, пароля, query и fragment; заголовок ограничен 300 символами. Запись
`saved_binding` помогает показать, с каким сайтом работала сессия, даже когда
прежняя вкладка закрыта. Она может быть устаревшей и не разрешает доступ к вкладке,
не создаёт группу и не открывает сайт автоматически.

MCP также запоминает запрошенный пользователем адрес в `mcp.requested_url`, даже
если первое подключение не удалось. В диагностике этот адрес очищен от query
и fragment. После восстановления состояние страницы проверяется новым снимком;
последний сохранённый адрес не заменяет такую проверку.

Для применения версии 0.9.0 один раз перезагрузите расширение и MCP-подключение.
